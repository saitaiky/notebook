This section connects the work of building software to the systems that run it. The material is organised as a path from
development fundamentals, through delivery and architecture, to Linux runtime behaviour and AWS service choices. You can
follow the path end to end or enter at the layer that matches the problem you are solving.

## Choose a learning path

| Goal                                          | Suggested path                                                                                                                                                                                                 |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Build and ship software reliably              | [SDLC](/software-development/sdlc/) → [Programming](/software-development/programming/) → [Version control](/software-development/version-control/) → [Delivery and operations](/software-development/devops/) |
| Design a production system                    | [System design](/software-development/system-design/) → [Data and databases](/software-development/database/) → [Authentication and identity](/software-development/authentication/)                           |
| Understand the runtime beneath an application | [Linux foundations](/linux/) → [Processes](/linux/process/) → [Filesystems](/linux/file-system/) → [Isolation with namespaces](/linux/namespace/)                                                              |
| Apply the concepts on AWS                     | [AWS overview](/aws/) → [Compute](/aws/compute/ec2/) → [Integration and messaging](/aws/integration-messaging/sqs/) → [Operations](/aws/management/cloudwatch/)                                                |
| Prepare for architecture interviews           | [Interview and communication](/software-development/interview/) after completing the relevant technical path above                                                                                             |

## Browse by area

- **[Programming](/software-development/programming/)** develops the language, complexity, asynchronous-programming, and
  refactoring foundations used by the rest of the site.
- **[Version control](/software-development/version-control/)** covers daily Git work and the merge strategies that
  support collaborative delivery.
- **[Delivery and operations](/software-development/devops/)** connects testing, CI/CD, observability, GitOps, and the
  “you build it, you run it” operating model.
- **[System design](/software-development/system-design/)** owns vendor-neutral architecture, APIs, scaling, messaging,
  security, and reliability trade-offs.
- **[Data and databases](/software-development/database/)** covers modelling, relational and NoSQL choices, query
  efficiency, and distributed data concerns.
- **[Authentication and identity](/software-development/authentication/)** explains identity providers, OAuth/OIDC,
  delegated access, and service identity.
- **[Cross-cutting architecture concepts](/software-development/others/)** collects operational topics that span several
  lifecycle stages, including monitoring, disaster recovery, storage, and quality.
- **[Interview and communication](/software-development/interview/)** turns the technical material into reusable
  stories, discovery conversations, demonstrations, and system-design responses.

## A practical reading method

For a new topic, I start with the vendor-neutral mechanism, inspect the Linux behaviour when the operating system
matters, and only then choose an AWS service. This sequence makes service comparisons easier because the decision is
anchored in a requirement—latency, consistency, isolation, delivery semantics, or operational ownership—rather than in a
list of product names.

Useful external references include [System Design 101](https://github.com/ByteByteGoHq/system-design-101),
[Awesome Scalability](https://github.com/binhnguyennus/awesome-scalability), and
[Kubernetes The Hard Way](https://github.com/kelseyhightower/kubernetes-the-hard-way). For local tooling, the relevant
notes are linked from [Python environments](/software-development/programming/python/pyenv-poetry/),
[Git basics](/software-development/version-control/basic/), and [Linux package management](/linux/package-manager/).
